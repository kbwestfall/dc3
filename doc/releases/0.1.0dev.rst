
Version 0.1.0dev
================

The first development version of ``dc3``, a Python reimplementation of the
detector-censored cross-correlation method of Westfall, Bershady & Verheijen
(2011, ApJS 193, 21).

Breaking Changes
----------------

- None. This is the initial development version; there is no prior release, and
  backwards compatibility with the original C++ implementation's file formats
  and command-line interface is explicitly not a design goal.

Documentation Updates
---------------------

- Added ``licenses/README.rst``, describing the terms of the third-party code
  ``dc3`` adapts (PypeIt, ``mangadap``) and the redistribution prohibition on
  ``ppxf``, which is a hard dependency but must never be vendored.

- Added the Sphinx documentation: a landing page, the release history, a
  development section, and the API reference, rendered with ``numpydoc``.

Dependency Changes
------------------

- Supports python 3.12, 3.13, and 3.14.

- ``ppxf`` is a hard dependency, floored at 9.5.0, for
  ``ppxf_util.varsmooth`` and ``ppxf_util.losvd_rfft``. Both the floor and the
  latest release are pinned as explicit ``tox`` axes, since both functions sit
  on the critical path.

- ``pydantic`` (v2) is a hard dependency; ``dc3.par.ParSet`` is built on it.

Functionality/Performance Improvements and Additions
----------------------------------------------------

- Initial repository scaffold: build configuration, licensing, continuous
  integration, and the ``dc3`` package tree.

- Added ``dc3.pkg``: logging, exceptions, the file cache, and the package
  data-path registry.

- Added ``dc3.par.ParSet``, the base class for all runtime parameters, built on
  ``pydantic`` v2. Supports reStructuredText table generation, a FITS header
  round-trip, a layered default/file/command-line merge, and TOML configuration
  files that carry parameter descriptions as comments.

- Added ``dc3.par.FuncPar``, a ``ParSet`` whose parameters are derived from the
  signature of a wrapped third-party function.

- Added the dc3 parameter sets themselves: ``TemplateLibraryPar``,
  ``TemplatePar``, ``ConvolvePar``, ``CorrelatePar``, ``MaskPar``,
  ``WindowPar``, ``ContinuumPar``, ``FitPar``, ``QAPar``, and the top-level
  ``DC3Par``. These expose a number of values that were hardwired in the C++
  implementation, including the apodization window, the sub-Nyquist convolution
  floor, the fit-window width, and the optimizer parameter scales.

- Added ``dc3.core.bitmask``, providing ``BitMask`` for the bit definitions and
  operations on raw integer values, and ``BitMaskArray`` for a mask array whose
  flags are read and set by name.

- Added ``dc3.scripts.scriptbase.ScriptBase``, the base class for the
  command-line scripts, which resolves a parameter set from a TOML
  configuration file layered with command-line overrides.

- Added the ``dc3_version`` script.

- Added ``dc3.core.velocity``, providing the conversions between velocity and
  redshift.

- Added ``dc3.core.sampling``, describing wavelength grids -- logarithmic,
  linear or irregular, with ``SpectralGrid`` -- and detecting which a
  wavelength vector has, with ``sampling_type``.

- Added ``dc3.core.resample``, providing the ``Resample`` class for
  flux-conserving resampling.

- Added ``dc3.spectra.Spectra``, the internal representation of a set of spectra
  sharing one logarithmic wavelength grid.  Instrumental resolution is carried
  as a dispersion in km/s, named ``idsp``; a resolving power supplied by a user
  is converted at ingest.

- Added ``dc3.core.resolution``, which computes the kernel that matches one
  spectral resolution to another and the signed instrumental variance
  ``dvar_inst`` it leaves behind, and applies it via ``ppxf_util.varsmooth``.

- Added ``dc3.core.deredshift``, which shifts a spectrum to the approximate
  rest frame by a whole number of pixels.  On a logarithmic grid this is a
  relabelling of the wavelength axis, so no flux is redistributed and no pixels
  are lost.

- Added ``dc3.templates``, providing ``TemplateLibrary`` and the two-step
  pipeline that prepares a library for fitting: resolution matching to a
  fiducial galaxy resolution, then resampling at an integer ``velscale_ratio``.
  The result carries the instrumental offset ``dvar_inst`` and a cache key
  covering everything that changes it.  Reading library files from disk is not
  yet implemented.

- Added ``DC3CodingError``, raised for a fault in ``dc3`` itself rather than in
  how it is used.

- Separated the definition of a template library, ``TemplateLibraryPar``, from
  the parameters governing how it is prepared for fitting, ``TemplatePar``.

- Added ``ParSet.to_kwargs``, which returns the parameters as Python objects so
  that a parameter set can be expanded over the keywords of the function it
  configures. ``dc3.templates.prepare`` is the first such function; a test
  checks that the two agree key for key and default for default.

- Added ``dc3.par.parset.document_parameters``, a decorator that fills a
  function's docstring Parameters section from the parameter set it is called
  with, so the two cannot carry different text.

- Parameter sets are now declared in the module whose code they configure:
  ``TemplateLibraryPar`` and ``TemplatePar`` moved to ``dc3.templates``.
  ``dc3.par`` provides the machinery, ``ParSet`` and ``FuncPar``, and
  ``dc3.par.dc3par`` the top-level ``DC3Par`` that nests the rest.

- Added ``ParSet.reachable``, which collects every parameter set nested below a
  given one.

- Template preparation no longer requires both resolution vectors. If the
  templates or the galaxy carry no instrumental dispersion, resolution matching
  is skipped with a warning and ``dvar_inst`` is zero. Added
  ``ResolutionMatch.identity`` and ``ResolutionMatch.performed``.

- ``TemplatePar.velscale_ratio`` accepts ``'auto'``, which selects the smallest
  ratio that keeps the prepared templates Nyquist-sampled. An explicit ratio
  that leaves them undersampled issues a warning. Added
  ``dc3.core.resolution.minimum_velscale_ratio``.

- Template preparation warns if a supplied instrumental dispersion is smaller
  than pixel integration alone would produce. Added
  ``dc3.core.resolution.check_pixelization``.

- Added ``dc3.core.sampling.grid_velocity_offset`` and
  ``PreparedTemplates.velocity_offset``, giving the constant velocity offset
  between template and galaxy grids of matched sampling.

- Added ``dc3.core.lsf``, for building spectra of lines of known width and
  measuring their pre- or post-pixelized widths.

- Added the template-preparation characterization: four scripts in
  ``doc/scripts/``, whose figures and tables are committed under
  ``doc/figures/characterization/`` and regenerated with ``make figures``.

- Template resampling now declares the input grid logarithmic when building
  its pixel borders.

- ``Spectra`` now holds a ``dc3.core.sampling.SpectralGrid``, which may be
  logarithmic, linear or irregular, and is constructed as
  ``Spectra(flux, grid)``. Template libraries are kept on their native grid and
  resampled once, during preparation. Removed
  ``dc3.core.sampling.grid_from_wave`` and ``TemplateLibraryPar.log10``.

- Added ``dc3.spectra.GalaxySpectra``, which requires a logarithmic grid.

- ``match_resolution``, ``ResolutionMatch`` and ``check_pixelization`` accept a
  velocity width per pixel.

- ``apply_kernel`` takes no coordinate argument, passes ``varsmooth`` pixel
  coordinates, and works around an upstream defect in ``varsmooth`` for an
  exactly uniform kernel.

- Template preparation detects jumps in the library's sampling and resolution
  and masks a band around each, flagged ``SAMP_JUMP`` or ``RES_JUMP``. Added
  ``SpectralGrid.breaks``, ``dc3.core.resolution.idsp_breaks``,
  ``TemplateLibraryPar.sampling_tol``, ``sampling_jump_tol`` and
  ``idsp_jump_tol``, and ``TemplatePar.convolution_mask_growth``.

- Template preparation masks the prepared templates around each run of pixels
  masked in the library, grown by ``convolution_mask_growth`` kernel
  dispersions, and flags them with the new ``TPL_MASKED`` bit.

- Added a fifth characterization, of jumps and masked gaps in the library, run
  with ``make splices``.

- Added the developer page ``doc/dev/template_preparation.rst``, summarizing
  the template-preparation characterization.

- ``TemplatePar.varsmooth_oversample`` must now be at least 2, and defaults to
  2. ``dc3.core.resolution.apply_kernel`` also defaults to 2 and refuses a
  smaller value.

- Template preparation corrects, by default, for the variance that resolution
  matching and resampling add to the line-spread function beyond what they are
  asked to, so the prepared templates reach the target resolution; where they
  cannot, the dispersion reported is the one achieved.  Added
  ``TemplatePar.correct_lsf_excess`` and ``resample_excess_method``,
  ``dc3.core.resolution.varsmooth_excess``, the ``varsmooth_oversample``
  argument of ``match_resolution``, and ``ResolutionMatch.achieved``.

- Added a characterization of the corrected pipeline, run with
  ``make correction``.

- The whole-pipeline characterization (``make preparation``) now prepares
  MILES-like templates for MaNGA-like data and compares the prepared resolution
  with the predicted excesses of resolution matching and resampling.

- Added a characterization of the pixel-size ratio Step 2 meets in production,
  for a linearly sampled library at ``velscale_ratio = 'auto'``, run with
  ``make velscale``.

- Added exploratory scripts in ``doc/scripts/`` comparing convolution methods,
  the effect of the kernel's dynamic range, and a kinematic-style kernel fit,
  and examining the choice of logarithmic sampling for a linearly sampled
  template library.

- The resolution-matching characterization (``make matching``) now compares
  ``varsmooth`` with its scalar path and ``gaussian_filter1d``, measures the
  second moment and a kinematic-style fit alongside the Gaussian fit, overlays
  the predicted excess, and adds a figure of the line-centre shift.
